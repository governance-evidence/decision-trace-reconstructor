# v0.2.0: separate evidence visibility and add typed decision checks

Local release preparation only. This text does not announce a published tag or DOI. DTR now distinguishes structural coverage from bounded evidence sufficiency and provides a reproducible Paper23 comparison against frozen V5 assessments.

## Breaking Changes

- Default coverage diagnostics can differ from v0.1.x: topology and participant count no longer imply missing evidence or decision diffusion.
- CLI feasibility reports include the assessment contract and actor inventory. Exact-output consumers need versioned expectations.

## Added

- Add `decision-evidence-v1` for typed, decision-bound authority, policy, request/receipt and final-state checks.
- Add the Paper23 packet adapter, retained-reference replay, twenty authored conformance cases and portable offline replication tooling.

## Changed

- Identify the default route as `fragment-coverage-v2`; full coverage does not certify semantic sufficiency.
- Include experimental runners in source distributions and the separate replication package. Keep the runtime wheel limited to the software package.

## Fixed

- Separate deployment topology, record visibility, record producers and declared agents.
- Align prepared software metadata at 0.2.0 and stop assigning historical release DOIs to the current source snapshot.

## Quality

- Run `make check` for lint, formatting, static types, the complete test suite and distribution builds.
- Verify the actual replication ZIP from a clean unpack and isolated runtime. The verifier must reproduce 432 original V5 rows, 432 retrospective rows, ten assessor controls and all twenty contract-case predictions.
- Check OEP against separate historical and 0.2.0 CLI expectations. Reject unreviewed versions.

## Migration

- Pin original v0.1.0 code and results for the historical Paper23 fixture evaluation. Do not regenerate `results/` to relabel old claims.
- Select the typed contract explicitly and follow `docs/evidence-contract.md`. Missing historical evidence bindings remain missing.
- Use the versioned OEP compatibility target when adopting 0.2.0.

## Notes

- Public API changed; DTR assessment/output contracts changed; external Decision Event Schema unchanged.
- The retrospective comparison and authored cases do not establish independent validity or superiority over a field-presence baseline.
- Before publication, the author must approve the final commit/tag and deposit, then add the actual version DOI and release date. Historical V5 files and earlier results remain immutable.
