# v0.2.0: separate evidence coverage from typed decision checks

Published 11 October 2026. Software archive: <https://doi.org/10.5281/zenodo.23297502>.

This release separates deployment topology from evidence visibility, distinguishes record producers from agents and action issuers, and adds an opt-in contract for typed decision evidence. It also adds offline replay tooling while preserving the original evaluation results.

## Added

- Add `decision-evidence-v1` for decision-bound authority scope, policy versions, request/receipt binding and independent final-state observations.
- Add a versioned retained-packet adapter, frozen-reference replay, twenty authored conformance cases and portable offline replication tooling via `experiments.replication` and the [replication guide](../replication-study.md). Experiment runners ship in the source distribution; frozen study data require the separate replication package.

## Changed

- Name the default route `fragment-coverage-v2`; `fully_fillable` on this route denotes structural coverage, not semantic sufficiency.
- Include the assessment contract in CLI and PROV-O reports and expose separate actor inventories in CLI JSON. Existing provider adapters continue to use the coverage route.

## Fixed

- Stop inferring evidence gaps or decision diffusion from topology or participant count alone.
- Run CI tests through `python -m pytest` so the experiment modules are importable, handle untyped optional PyArrow imports, and align the Mypy environment with its Python 3.11 target.

## Migration

- Update exact-output expectations: default scores and diagnostics can differ from v0.1.x, and reports contain new contract and actor fields. Use versioned expectations for OEP consumers.
- Select the typed route with `"evidence_contract": "decision-evidence-v1"` in the input manifest and supply the documented roles and bindings. Missing historical evidence is not synthesized.
- Pin v0.1.0 to reproduce the original fixture evaluation. The committed `results/`, frozen V5 assessments and previous study results remain tied to their preserved instruments.

## Notes

- public API and DTR assessment/output contracts changed
- external Decision Event Schema and generic-jsonl mapping contract unchanged
- typed checks do not authenticate records or establish task correctness; retrospective agreement and authored conformance cases do not establish independent validation or baseline superiority
